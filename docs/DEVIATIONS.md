## Новое по сравнению со скриптом (в режиме паритета не влияет)

- Отпуска по датам (`Worker.absent_days`) и удержание с датой снятия (`Operation.hold_until`) — поддержаны планировщиком и покрыты тестами; в Excel-формате листов для них пока нет столбцов.
- `reason_code` (FREE_CAPACITY / AFTER_DEADLINE / FROZEN) и типизированные предупреждения (BR-18, BR-19).
- «Сегодня» — по часовому поясу (по умолчанию Europe/Moscow), передаётся в планировщик явно.

## Мутационная проверка набора паритета

Преднамеренные поломки правил (округление, лимит людей на операцию, порог загрузки, заморозка, готовность групп, граница жёсткости) ловятся тестами. Единственный неуловимый мутант — `>` вместо `>=` в `prio_share_day` — эквивалентен из-за допуска 1e-9.

## Решения, принятые при построении сервиса (нужно подтверждение)

| № | Вопрос | Что сделано |
|---|--------|-------------|
| D-06 | Бригадир перепланирует только свой участок (решение владельца) | **Реализовано.** Бригадир перепланирует только свой участок; руководитель — всю организацию или выбранный участок. Задания исполнителей других участков переносятся в новый план без изменений (с их признаками «зафиксировано»/причиной); сделанное по ним вычитается. Частичное перепланирование возможно только поверх существующего общего плана (иначе 409). Подробности и ограничения — ниже, D-16. |
| D-07 | Изделие с позициями на разных версиях маршрута | Планировщик получает ключ «Изделие (vN)» только если в плане одновременно используется несколько версий; иначе — просто имя. Структура маршрута, на котором стоят позиции, неизменяема (409); блокировка операции («Блок») редактируется всегда. |
| D-08 | Неподтверждённый факт сборщика при включённом подтверждении | Учитывается в расчёте сразу (виден как «ждёт подтверждения»). Альтернатива — не учитывать до подтверждения; сейчас выбран вариант, при котором план не врёт о выработке. |
| D-09 | Факт можно вносить: сборщик — только за сегодня и только свой; бригадир — свой участок, за любую прошлую дату; на будущее — никому | Следует ТЗ; на выходных «сегодня» не рабочий день, поэтому плана на сегодня нет. |
| D-10 | Повторный ввод факта | Заменяет значение за (дата, позиция, операция, исполнитель); прежнее значение остаётся в журнале. |
| D-11 | Единицы измерения | Строка `unit` у изделия и операции, а не отдельный справочник. |

## Исправленные дефекты при разработке (регрессии покрыты тестами)

- Поздний коммит: по умолчанию FastAPI завершает зависимости с `yield` **после** отправки ответа, клиент мог прочитать ещё не сохранённое (после регистрации следующий запрос получал 401). Коммит теперь до ответа (`scope="function"`). Тест: `test_commit_happens_before_response_is_sent`.
- SQLite: чтение без общей транзакции давало рассогласованные данные внутри одного расчёта. Включены явные транзакции и WAL; запись — `BEGIN IMMEDIATE`. Тесты: `test_sqlite_reader_sees_one_consistent_snapshot`, `test_concurrent_writers_and_readers_never_get_server_errors`.
- Допуск «никому не разрешено» превращался в «разрешено всем» (в скрипте — предупреждение). Набор паритета `edge_order_nobody_allowed`.
- Интерфейс: запоздавший ответ прежнего экрана перерисовывал другую вкладку. Регрессия в `tests_ui/smoke.js`.
