# Скрипт распределения заданий

Файл `Code_v3.5.gs` заменяет код целиком. Сначала проверьте на **копии таблицы**: тесты шли на эмуляторе Google Sheets, а не на живой таблице.

## Версия 3.5 — рекомендация в «Статусе заказов», столбец L

- На листе «Статус заказов» появился столбец L «Что нужно, чтобы успеть». Данные берутся из расчёта в отчёте по проекту, по каждой партии (ID) отдельно.
  - Не успевает: «Добавить 2 чел. на 6 раб. дн. (14.10–21.10); отставание 2 раб. дн.» — сколько людей добавить, на какое окно рабочих дней (от старта заказа в плане до срока) и на сколько рабочих дней заказ опаздывает. Если причина в приоритете, дописывается совет снизить жёсткость на листе «Настройки».
  - Людьми не исправить (срок прошёл или заказ стартует после срока): вместо числа людей — совет сдвинуть срок.
  - Успевает: «В срок» (зелёная ячейка). Выполнен, без плана или без операций: пусто.
  - Заказы проектов, по которым отчёт не строится, остаются без записи.
- **Исправлена ошибка расчёта отставания.** Если срок выпадал на выходной или был в прошлом, отставание считалось как 0, а блок «Нужно добавить людей» вообще не появлялся (заказ при этом был «Риск опоздания»). Теперь отставание считается в рабочих днях между сроком и прогнозом завершения, в том числе для просроченных сроков.
- Проверка: `node tests/test35.js`.

## Версия 3.4 — партии (несколько заказов одного изделия в проекте)

Пример: заказы 307-71 (18 шт., срок 30.09), 307-72 (6 шт., 12.10), 307-73 (7 шт., 19.10) — один проект, одно изделие «Флагман Смарт».

- **Факт считается по связке проект — изделие — операция, ID не важен.** Выполненный объём раскладывается по партиям в порядке сроков: сначала закрывается партия с ближайшим сроком, затем следующая; излишек уходит на последнюю партию. Поэтому неважно, в строке какого ID внесён факт; строка с пустым или устаревшим ID тоже учитывается.
- **В отчёте строки «Изделие — Операция»**, а не «ID — Операция»: ПЛАН, ФАКТ, ОТКЛОНЕНИЕ, «ГОТОВЫХ <изделие>», выходы суммируются по всем партиям проекта. Заголовок столбца переименован в «Изделие — Операция». Список причин отставания тоже строится по проекту без привязки к ID.
- **Планирование ресурсов остаётся по партиям:** отдельный блок на каждый ID со своим сроком, прогнозом и рекомендациями. Факт для него берётся из той же FIFO-раскладки, что и в планировщике, поэтому цифры согласованы.
- **Количество в таблице «Заказы» можно писать с текстом:** «18шт. к» → 18, «6 шт.» → 6, «1 200» → 1200, «2,5» → 2,5. Раньше такое значение читалось как 0.
- Планирование (ID, сроки, приоритеты) по-прежнему по партиям: у каждой партии свой срок. Заморозка плана на сегодня и завтра тоже по ID.
- Проверка: `node tests/test34.js`. На данных из примера факт 20 операций «Раскрой», внесённый на партию 307-72, закрывает партию 307-71 (18) и уменьшает остаток партии 307-72 до 4; в плане по 307-71 «Раскрой» = 0.

## Версия 3.3 — причины отставания в отчёте по проекту

- В отчёте появился раздел «ПРИЧИНЫ ОТСТАВАНИЯ» (перед планированием ресурсов). Данные берутся из столбца I «Причина отклонения» листа «Факт».
- Учитываются только случаи, когда сделано меньше плана (в том числе ноль). Перевыполнение и строки без внесённого факта в список не попадают.
- Одинаковые причины объединяются независимо от регистра и лишних пробелов. Для каждой причины показано число случаев, сколько операций недовыполнено и до 4 примеров (дата, операция, сборщик, размер отставания). Причины идут от самой «дорогой» к менее значимым.
- Последняя строка «Причина не указана» (жёлтая) показывает, сколько отставаний осталось без причины, и напоминает вписать их на листе «Факт».
- Если отставаний нет, раздел в отчёте не выводится.
- Проверка: `node tests/test33.js`.

## Версия 3.2 — причина отклонения на листе «Факт»

- Новый столбец I «Причина отклонения» (для существующего листа заголовок и ширина добавляются автоматически при запуске).
- Ячейка I подсвечивается **жёлтым**, если факт внесён, отличается от плана (и меньше, и больше) и причина ещё не вписана. Внеплановая работа (плана нет) тоже подсвечивается. Как только вписан текст, подсветка исчезает. Пока факт не внесён, ячейка не подсвечивается.
- Сортировка листа теперь захватывает столбец I, поэтому причины не отрываются от своих строк.
- Строка с нулевым фактом и вписанной причиной (например, «больничный») больше не удаляется при пересчёте. Строки с нулём без причины удаляются, как раньше.
- Правило подсветки записано без разделителей аргументов, поэтому работает в любой локали таблицы.
- Проверка: `node tests/test32.js`.

## Версия 3.1 — правки по замечаниям

1. **«Стрелки» на границах ячеек.** Вероятная причина — закрепление строк и столбцов: на его границе Google Sheets показывает «ручку» для перетаскивания. Закрепление отключено на всех листах скрипта, а на уже существующих листах снимается при каждом запуске. Если стрелки останутся, пришлите, на каком листе и в каком месте — причина другая. Вернуть закрепление: `FREEZE_HEADERS = true` в начале кода.
2. **Одно сообщение — в конце.** Итоговое окно теперь появляется только после завершения всех шагов (план, загрузка, статусы, отчёты) и содержит: число строк плана, предупреждения, сколько отчётов создано, по каким проектам отчёта нет.
3. **Отчёты только по проектам с планом.** Проекты без операций или без плана работ пропускаются. Устаревшие листы «Отчёт: …» (проекта больше нет в плане) удаляются. Побочный эффект: полностью выполненный проект, у которого не осталось плановых строк, тоже отчёта не получит.
4. **Ширина столбцов в отчёте.** A — 330, B — 95. Длинные тексты (узкие места, что делать) объединяются по ширине B…K с переносом, высота строки подбирается автоматически.
5. **Планирование ресурсов — только главное.**
   - По заказу: «Успеем к сроку», «Прогноз завершения».
   - Если заказ не успевает: «Отставание, раб. дней», «Нужно добавить людей», «Узкие места», «Что делать».
   - Сводка по проекту — только если в проекте больше одного заказа.
   - Убраны служебные строки: сборщиков всего, занято, доступно, остаток нормо-дней, смены, «требуется всего», рабочие дни до срока и др.
   - «Что делать» очищено: без строк «взять на контроль», числа людей ограничены лимитом на операцию (раньше выходило вроде «добавить 36 чел.»), грамматика исправлена.
   - Если заказ не успевает из-за того, что стартует поздно по приоритету, отчёт подсказывает снизить жёсткость на листе «Настройки».

## Версия 3.0
- Убран коэффициент 0,85: норма — выработка за полный день, ёмкость = норма × производительность. Ёмкость выросла примерно на 18%, сроки сдвинутся раньше; если цех был настроен под 0,85, умножьте нормы на 0,85.
- Только целые операции. Целая операция ставится, если в остатке дня хватает времени на неё или на 50% её времени (параметр в «Настройках»); излишек переносится на следующий рабочий день сборщика. Дробная кратность «на изделие» округляется вверх.
- Нехватка людей на критическом пути: `ceil(просрочено нормо-дней / (средняя выработка × рабочих дней от старта заказа до срока))`, с ограничением лимитом людей на операцию; в сводке максимум по заказам, а не сумма. Исправлено усреднение занятости прошлых заказов.
- Лист «Настройки»: жёсткость приоритета (0–100%, можно по уровням, например `2:60; 3:30`), макс. сборщиков на операцию, порог загрузки сегодня, мин. доля операции для старта.
- Исправлены имена листов отчётов (раньше название проекта обрезалось до 3 символов) и ошибки на пустых листах.

## Что важно знать
- Эмулятор не воспроизводит всё поведение Google Sheets (оформление, лимиты по времени выполнения).
- «Факт» по-прежнему связан с планом по ID и названию операции; переименование операции ломает связь.
- Не реализовано: отпуска по датам, передача партиями, удержание с датой снятия, часовой пояс организации. Эти пункты пойдут в сервис.
